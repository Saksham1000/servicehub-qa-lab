# Agile QA Workflow
QA joins backlog refinement to challenge ambiguity, examples, dependencies, observability, and testability. Definition of Ready: user value, scoped acceptance criteria, designs/API contract, dependencies, test data, risk, and estimates understood. In sprint planning QA maps risk and test work. During development QA reviews contracts, prepares data/automation, and tests slices early. Defects are triaged collaboratively; fixes receive targeted regression. Sprint demo shows acceptance evidence, not just the happy path. Release adds project-level regression, risk review, checklist, and recommendation.

Definition of Done includes reviewed code, acceptance criteria met, unit/integration/QA checks passing, authorization and negative paths covered, documentation/RTM updated, no unacceptable defects, and deploy/rollback readiness. Sprint testing validates stories; module testing examines a domain and integrations; project/release testing covers end-to-end change interaction and operational readiness.
